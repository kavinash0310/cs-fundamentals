# Software Engineering and System Design

A practical course from requirements to production operation, with design trade-offs and interview exercises.

## Chapter sequence

| Chapter | Coverage |
|---|---|
| [1. Requirements, lifecycle, and agile](software-engineering-system-design/chapter-01-requirements-lifecycle-and-agile.md) | Functional/non-functional needs, acceptance criteria, planning, feedback |
| [2. Modularity, architecture, and APIs](software-engineering-system-design/chapter-02-modularity-architecture-and-apis.md) | Boundaries, architecture styles, API contracts, data ownership |
| [3. Testing, quality, Git, and delivery](software-engineering-system-design/chapter-03-testing-quality-git-and-delivery.md) | Test levels, doubles, debugging, version control, CI/CD, rollout |
| [4. Scalability, reliability, and system design](software-engineering-system-design/chapter-04-scalability-reliability-and-system-design.md) | Capacity, caches, queues, failure handling, consistency, observability |
| [5. Design review and interview workbook](software-engineering-system-design/chapter-05-design-review-and-interview-workbook.md) | Review checklist, rate limiter, upload service, trade-off practice |

Interview loops differ by company, role, and level. Treat the examples as practice frameworks, not a guarantee of a particular interview.
